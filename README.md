# Test-Driven Development

## Objective

Work in pairs.

One person is the Driver.
One person is the Navigator.

The Driver writes the code.
The Navigator thinks about design, requirements and test cases.

Switch roles after 30 minutes.

## Rules

1. Start with a failing test.
2. Write only enough code to make the test pass.
3. Refactor when green.
4. Keep commits small.
5. Discuss design decisions openly.
6. Resist implementing future requirements before a test demands it.

## Suggested Workflow

Red → Green → Refactor

Repeat.

## Challenges

Choose one challenge for the first session.

After 30 minutes switch challenge and switch roles.

The objective is not to finish.

The objective is to experience test-driving a design into existence.
